# 阶段1 版本说明书（MVP）

## 本阶段使用的技术及解决的问题

- **Spring Boot 3.3.5**：快速搭建后端服务，统一管理 Web、Redis、MyBatis 等组件。
- **MySQL 8**：持久化短链映射、原始链接、过期时间、点击次数。
- **Redis**：用 String 缓存“短码 → 原链接”，减少跳转时对数据库的读取压力。
- **MyBatis-Plus**：简化数据库操作，并提供分页查询。
- **自增 ID + 62 进制**：生成唯一短码，避免哈希碰撞。
- **HTTP 302 临时重定向**：跳转时不缓存，确保每次点击都回到服务端统计。
- **Vue 3 + Vite**：构建前端单页应用，提升开发与构建体验。
- **Element Plus + axios**：提供表单、表格、分页等 UI，并统一封装接口请求。
- **统一返回与全局异常处理**：让接口返回格式一致，异常可集中处理。

## 工作流程

### 1. 创建短链

- 前端调用 `POST /api/short-url/create`。
- `ShortUrlController.create()` 接收参数并校验。
- 调用 `IShortUrlService.createShortUrl()`。
- 在 `ShortUrlServiceImpl.createShortUrl()` 中：
  - 先调用 `ShortUrlMapper.selectOne()` 判断该长链是否已存在，存在则直接返回。
  - 不存在时调用 `ShortUrlMapper.insert()` 插入一条 `short_code` 为空的数据，获得自增 ID。
  - 用 `Base62Utils.encode()` 把自增 ID 转成短码。
  - 调用 `ShortUrlMapper.updateById()` 把短码更新回数据库。
  - 调用 `redisTemplate.opsForValue().set()` 写入 Redis 缓存，TTL 为 7 天。
- 返回 `ShortUrlVO` 给前端。

### 2. 短链跳转

- 用户访问 `GET /{shortCode}`。
- `ShortUrlController.redirect()` 接收短码并调用 `IShortUrlService.getOriginalUrl()`。
- 在 `ShortUrlServiceImpl.getOriginalUrl()` 中：
  - 先用 `redisTemplate.opsForValue().get()` 查 Redis。
  - 缓存命中时，直接统计点击并返回原链接。
  - 缓存未命中时，调用 `ShortUrlMapper.selectOne()` 查数据库。
  - 若记录不存在或已过期，返回 `null`。
  - 查询成功后，把原链接回写到 Redis。
  - 统计点击时，调用 `ShortUrlMapper.update()` 执行 `click_count = click_count + 1`。
- Controller 收到原链接后，设置 `302` 和 `Location`，浏览器完成跳转。

### 3. 短链列表

- 前端调用 `GET /api/short-url/list`。
- `ShortUrlController.list()` 接收分页参数。
- 调用 `IShortUrlService.page()`。
- 在 `ShortUrlServiceImpl.page()` 中：
  - 调用 `ShortUrlMapper.selectPage()` 查询分页数据。
  - 将 `ShortUrl` 转换为 `ShortUrlVO`。
- Controller 返回 `R<Page<ShortUrlVO>>` 给前端展示。

## 现阶段遗留问题

- 跳转时同步更新点击次数，高并发下数据库写压力较大，计划用 RabbitMQ 异步化。
- 短链过期目前主要依赖查询时判断，缺少统一的定时清理。
- 当前为单体应用，后续可拆分服务并引入分布式缓存。
